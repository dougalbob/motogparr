VERIFY-ADMIN ROUTE (/verify-admin):
The original implementation used a non-existent load_settings() function.
Fixed to directly read settings.yml with proper error handling:

    @app.route('/verify-admin', methods=['POST'])
    def verify_admin():
        import yaml
        data = request.get_json()
        password = data.get("password", "") if data else ""
        
        try:
            settings_file = CONFIG_DIR / "settings.yml"
            if settings_file.exists():
                with open(settings_file, "r") as f:
                    settings = yaml.safe_load(f)
                    admin_password = settings.get("uiadminpassword", "")
                    if admin_password and password == admin_password:
                        return jsonify({"valid": True})
        except Exception as e:
            print(f"Error verifying admin password: {e}")
        
        return jsonify({"valid": False})

PART 2: STATUS LABEL BUG - DETAILED ANALYSIS AND SOLUTION
================================================================================

This section provides comprehensive detail for implementing the same fix in F1arr.

--------------------------------------------------------------------------------
2.1 PROBLEM DESCRIPTION
--------------------------------------------------------------------------------

SYMPTOM:
When downloading episodes from multiple rounds, the status label in the header
would display the first job correctly but fail to update for subsequent jobs.

Example observed behavior:
- Selected: E01,E22 from Round 1, E10 from Round 3
- Label showed: "Running: Searching (1/2): Season 2025 R1 E22,E01"
- Label NEVER updated to show "(2/2)" for Round 3
- Downloads completed successfully (backend working correctly)
- Label only updated after manual page refresh

AFFECTED PAGES:
- Activity tab
- Logs tab
- Any page where noReloadPages prevents auto-refresh

--------------------------------------------------------------------------------
2.2 ROOT CAUSE ANALYSIS
--------------------------------------------------------------------------------

The issue has multiple contributing factors:

FACTOR 1: PAGE AUTO-RELOAD EXCLUSION
In base.html, certain pages are excluded from auto-reload:

    const noReloadPages = ['activity', 'logs'];        
    if (!noReloadPages.includes(currentTab)) {
        setTimeout(() => location.reload(), 3000);
    }

Activity and Logs pages use streaming/EventSource for live updates of their
content, so full page reloads are disabled. However, the status label in the
header is NOT updated by the streaming mechanism.

FACTOR 2: MULTI-COMMAND EXECUTION FLOW
When user selects episodes from multiple rounds, the download-selected route:
1. Groups selections by round
2. Creates separate backfill commands for each round
3. Runs commands sequentially via run_all_commands()

The command_output["command"] IS updated at the start of each command, but
the Activity page never fetches this updated value.

FACTOR 3: SERVER-SIDE RENDERING
The status label is rendered server-side in base.html:

    <div class="status {{ 'running' if status.running else 'ready' }}">
        {% if status.running %}⏳ Running: {{ status.command }}
        {% else %}✅ Idle{% endif %}
    </div>

This only updates on page load/reload. Without polling, it remains stale.

--------------------------------------------------------------------------------
2.3 SOLUTION IMPLEMENTED
--------------------------------------------------------------------------------

APPROACH: Add client-side polling for status label on non-reloading pages.

The /status endpoint already exists and returns command_output:

    @app.route("/status")
    def status():
        return jsonify(command_output)

Returns:
    {
        "running": true/false,
        "command": "current command string",
        "output": "command output text",
        "timestamp": "2025-02-05 09:30:00",
        "batch_total": 2,
        "batch_current": 1
    }

IMPLEMENTATION IN BASE.HTML:

Added after the existing noReloadPages definition:

    // Status polling for pages that don't auto-reload
    const noReloadPages = ['activity', 'logs'];
    let statusPollInterval = null;
    
    function updateStatusLabel() {
        fetch('/status')
            .then(r => r.json())
            .then(data => {
                const statusEl = document.querySelector('.header-row .status');
                if (statusEl) {
                    if (data.running) {
                        statusEl.className = 'status running';
                        statusEl.innerHTML = '⏳ Running: ' + data.command;
                    } else {
                        statusEl.className = 'status ready';
                        statusEl.innerHTML = '✅ Idle';
                        // Stop polling when idle
                        if (statusPollInterval) {
                            clearInterval(statusPollInterval);
                            statusPollInterval = null;
                        }
                    }
                }
            })
            .catch(err => console.log('Status poll error:', err));
    }
    
    function startStatusPolling() {
        if (!statusPollInterval) {
            updateStatusLabel(); // Immediate first update
            statusPollInterval = setInterval(updateStatusLabel, 3000);
        }
    }
    
    {% if status.running %}
    if (!noReloadPages.includes(currentTab)) {
        // Regular pages: full reload
        setTimeout(() => location.reload(), 3000);
    } else {
        // Activity/Logs pages: poll status label only
        startStatusPolling();
    }
    {% else %}
    // Even when idle, start polling on activity page to catch new jobs
    if (noReloadPages.includes(currentTab)) {
        startStatusPolling();
    }
    {% endif %}

KEY DESIGN DECISIONS:

1. POLLING INTERVAL: 3000ms matches the existing reload interval for consistency

2. IMMEDIATE FIRST UPDATE: updateStatusLabel() called immediately before 
   setInterval to avoid 3-second delay on page load

3. AUTO-STOP ON IDLE: Polling stops when status.running becomes false to 
   conserve resources. This is important for mobile/PWA usage.

4. ALWAYS POLL ON ACTIVITY PAGE: Even when initially idle, polling starts
   on Activity page so it detects when new jobs begin

5. MINIMAL DOM UPDATES: Only the status label element is updated, not the
   entire page. This preserves the streaming activity feed state.

2.4 ENHANCED BATCH STATUS DISPLAY
--------------------------------------------------------------------------------

The run_all_commands function was also enhanced to provide clearer status:

COMMAND_OUTPUT STRUCTURE (Extended):
    command_output = {
        "running": False,
        "command": "",
        "output": "",
        "timestamp": None,
        "batch_total": 0,      # NEW: Total commands in batch
        "batch_current": 0     # NEW: Current command number
    }

RUN_ALL_COMMANDS FUNCTION (in download-selected route):

    def run_all_commands(cmds, season, round_info):
        global command_output
        total = len(cmds)
        command_output["batch_total"] = total
        
        for i, (cmd, info) in enumerate(zip(cmds, round_info)):
            command_output["running"] = True
            command_output["batch_current"] = i + 1
            round_num = info["round"]
            episodes = info["episodes"]
            
            # Clear status format for UI display
            command_output["command"] = f"Searching ({i+1}/{total}): Season {season} R{round_num} {episodes}"
            command_output["timestamp"] = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
            
            # Enhanced output logging
            if i == 0:
                command_output["output"] = f"Starting batch download of {total} job(s)...\n\n"
            else:
                command_output["output"] += f"\n{'='*60}\n"
            
            command_output["output"] += f">>> Search {i+1}/{total}: Season {season} Round {round_num} - {episodes}\n\n"
            
            # Execute command...
            
        # Only set running=False after ALL commands complete
        command_output["running"] = False
        command_output["batch_total"] = 0
        command_output["batch_current"] = 0
        command_output["output"] += f"\n{'='*60}\n✅ All {total} searches completed.\n"

STATUS LABEL OUTPUT FORMAT:
    "Searching (1/2): Season 2025 R15 E01,E22"
    "Searching (2/2): Season 2025 R3 E10"

This format clearly shows:
- Current job number / Total jobs
- Season being searched
- Round number
- Episode(s) for that round
